# 콘텐츠 이용 패턴과 연속 구독 유지 분석 프로세스 정리

## 분석 목적

본 분석의 목적은 구독 유지 기간이 상이한 유저 집단이 소비하는 콘텐츠의 특성을 비교하고, 이를 바탕으로 장기 구독과 콘텐츠 요인 간의 상관관계를 탐색하는 데 있다.

단순히 구독 유지 기간의 길이를 확인하는 것만으로는 장기 구독의 배경을 충분히 설명하기 어렵다. 이에 따라 본 분석에서는 유저를 연속 구독 유지 패턴에 따라 구분한 뒤, 각 집단이 실제로 소비한 콘텐츠의 난이도와 인기도 수준에 차이가 존재하는지를 확인하고자 하였다.

구체적으로는 다음과 같은 질문에 답하고자 한다.

- 구독 유지 기간이 짧은 유저와 긴 유저는 서로 다른 난이도의 콘텐츠를 소비하는가
- 장기 유지 집단은 상대적으로 더 인기 있는 콘텐츠를 소비하는 경향을 보이는가
- 월간 유지형 유저와 연간 플랜이 포함된 유저는 콘텐츠 소비 패턴 측면에서 어떠한 차이를 보이는가

이를 위해 본 분석은 두 단계로 구성하였다.

첫째, 구독 로그를 정제하여 유저별 구독 유지 구조를 정의하였다. 이 단계에서는 첫 연속 구독 길이, 최장 연속 구독 길이, 전체 유료 구독 개월 수, 재활성화 여부 등 구독 유지와 관련된 핵심 지표를 산출하고, 이를 바탕으로 분석용 유지 그룹을 구성하였다.

둘째, 콘텐츠 로그에 콘텐츠 메타 정보를 결합하여 유지 그룹별 콘텐츠 소비 특성을 비교하였다. 이 단계에서는 콘텐츠 난이도와 글로벌 인기도 지표를 기준으로, 각 유지 그룹이 어떠한 콘텐츠를 시작하고 완료하는지 분포와 요약 통계 수준에서 분석하였다.

따라서 본 문서는 유저 유지 구조를 정의한 과정과 콘텐츠 메타 지표를 설계한 과정을 함께 정리하고, 최종적으로 유지 그룹별 콘텐츠 소비 특징을 비교하기 위한 분석 프레임을 보고서 형태로 정리하는 것을 목적으로 한다.

## 1. 유저 마스터 테이블을 정의한 이유

이번 분석의 핵심 질문은 다음과 같았다.

- 어떤 유저가 더 오래 연속 구독을 유지하는가
- 오래 유지한 유저는 어떤 콘텐츠를 소비하는가
- 첫 구독 이후의 유지 패턴과 콘텐츠 이용 패턴 사이에 어떤 차이가 있는가

이를 위해서는 이벤트 로그 단위가 아니라, **유저 단위 기준 테이블**이 먼저 필요했다.  
원시 `complete_subscription`, `renew_subscription`, `resubscribe_subscription` 로그는 같은 유저가 여러 번 결제 시도를 남기거나, 같은 날 중복 로그가 찍히는 문제가 있어 그대로 사용하기 어려웠다.

따라서 분석에서는 먼저 **유저별 첫 구독 시점과 구독 유지 관련 지표를 정리한 마스터 테이블**을 만들고, 이후 콘텐츠 로그를 이 유저 마스터에 붙여 분석하는 구조를 채택했다.

## 2. 유저 마스터 테이블 정의 과정

### 2-1. 원천 로그 정리

사용한 구독 관련 로그는 다음 3개다.

- `complete_subscription`
- `renew_subscription`
- `resubscribe_subscription`

먼저 각 테이블에서 같은 유저의 짧은 기간 내 반복 결제 시도를 하나의 구매 시도로 압축했다.

- 기준: `PURCHASE_WINDOW_DAYS = 7`
- 처리 방식: 같은 유저의 결제 로그가 7일 이내로 반복되면 같은 구매 시도로 보고 마지막 로그만 남김

이 단계의 목적은 다음과 같다.

- 결제 페이지 진입 후 망설이며 여러 번 버튼을 누른 경우 제거
- 완전히 동일한 중복 로그 제거
- 실제 결제 횟수보다 과대 집계되는 문제 완화

### 2-2. 연속 구독 체인 계산

정제된 `complete + renew + resubscribe` 로그를 시간순으로 읽으면서 유저별 구독 체인을 계산했다.

연속 구독으로 인정한 기준은 다음과 같다.

- 기존 만료일 기준 `7일 전 ~ 7일 후` 사이 결제는 같은 체인으로 인정
- 만료일보다 너무 이른 결제는 중복 시도/겹침 로그로 보고 제외
- 만료 후 허용 구간보다 늦은 결제는 새 체인으로 분리

즉, 한 유저의 구독 로그는 다음처럼 여러 체인으로 나뉠 수 있다.

- 첫 체인: 첫 구독부터 첫 끊김까지
- 두 번째 체인: gap 이후 재구독
- 세 번째 체인: 다시 gap 이후 재구독

### 2-3. 유저 마스터(v2, v3, v4) 생성

#### `complete_subscription_kr_master_v2`

`v2`는 구독 로그 기반 유저 마스터다.  
유저별 첫 결제 정보와 구독 유지 관련 지표를 포함한다.

포함 지표:

- `first_sub_time`: 유저의 첫 구독 시각
- `plan.price`: 첫 구독 시점 결제 금액
- `first_plan_type`: 첫 결제가 월간인지 연간인지
- `first_chain_months`: 첫 구독부터 첫 끊김까지의 연속 구독 개월 수
- `max_chain_months`: 전체 체인 중 최장 연속 구독 개월 수
- `total_paid_months`: 전체 유료 구독 개월 수 합
- `reactivated_after_gap`: 끊긴 뒤 다시 돌아온 적 있는지 여부
- `annual_in_first_chain`: 첫 번째 체인 안에 연간 플랜이 한 번이라도 포함되었는지 여부
- `consecutive_sub_months`: 기존 코드 호환용 alias. 현재는 `first_chain_months`와 같은 의미

#### `complete_subscription_kr_master_v3`

`v3`는 `v2`에 회원가입 정보를 결합한 버전이다.

추가 컬럼:

- `signup_time`
- `signup_type`
- `time_to_first_payment_days`

`time_to_first_payment_days`는 가입 후 첫 결제까지 걸린 시간을 일(day) 단위로 계산한 값이다.

#### `complete_subscription_kr_master_v4`

`v4`는 `v3`에 최종 분석용 세그먼트 컬럼을 부착한 버전이다.

추가 컬럼:

- `seg_4grp`

정의:

- `0_to_2m`: `first_chain_months < 3`
- `3_to_5m`: `3 <= first_chain_months < 6`
- `6m_plus_monthly_only`: `first_chain_months >= 6` 이고 `annual_in_first_chain == False`
- `with_annual_in_first_chain`: `annual_in_first_chain == True`

### 2-4. 왜 이런 지표가 필요한가

처음에는 단순히 `consecutive_sub_months`만으로 유저를 나누려 했지만, 다음 문제가 있었다.

- `12개월`이라는 숫자 하나에
  - 연간 플랜 1회 결제 유저
  - 월간 플랜을 12회 연속 유지한 유저
  가 동시에 섞임
- 첫 체인이 끊긴 후 나중에 다시 오래 유지한 유저를 하나의 숫자로 설명하기 어려움

그래서 한 개 지표로 모든 행동을 설명하기보다 다음을 분리했다.

- 첫 유지력: `first_chain_months`
- 최장 유지력: `max_chain_months`
- 총 결제량: `total_paid_months`
- 재활성화 경험: `reactivated_after_gap`
- 연간 포함 여부: `annual_in_first_chain`

## 3. 콘텐츠 인기도 지표를 고안한 과정

초기에는 콘텐츠를 `관심도`와 `진입도`의 2축으로 나누어 4사분면으로 분류하려 했다.

- `interest_count`: `enter_content_page` 이벤트 수
- `start_count`: `start_content` 이벤트 수

그리고 이를 바탕으로 다음과 같이 나누려 했다.

- High 관심도 / High 진입도
- High 관심도 / Low 진입도
- Low 관심도 / High 진입도
- Low 관심도 / Low 진입도

하지만 실제 데이터에 적용해보니, 콘텐츠가 특정 사분면에 과도하게 몰리면서 정보량이 거의 사라졌다.  
즉 사분면 분류 자체가 결과 해석에 큰 도움을 주지 못했다.

그래서 현재는 **사분면 분류를 폐기**하고, 콘텐츠별 글로벌 인기 지표 자체를 메타값으로 유지하는 방향으로 수정했다.

현재 사용하는 인기도 지표:

- `interest_count`: 전체 `enter_content_page` 이벤트 수
- `start_count`: 전체 `start_content` 이벤트 수

이 두 값은 **유저 마스터 기준이 아니라 전체 콘텐츠 로그 기준**으로 계산한다.  
이유는 먼저 콘텐츠 자체의 특성을 정의한 뒤, 각 유저 그룹이 어떤 인기도 수준의 콘텐츠를 소비하는지 비교하기 위함이다.

즉 현재 인기도 분석 질문은 다음과 같다.

- 어떤 유지 그룹이 평균적으로 더 관심도가 높은 콘텐츠를 시작하는가
- 어떤 유지 그룹이 실제 진입도가 높은 콘텐츠를 더 많이 완료하는가

## 4. 유저-콘텐츠 결합 과정

분석 구조는 크게 두 단계다.

### 4-1. 콘텐츠 메타 생성

먼저 콘텐츠별 메타 테이블을 만든다.

- `content_difficulty_final`
  - `start_content`에서 관측된 가장 마지막 난이도를 해당 콘텐츠의 대표 난이도로 사용
- `content_popularity_metrics`
  - 콘텐츠별 `interest_count`, `start_count`

이 메타는 `content.id` 단위 기준이다.

### 4-2. 이벤트 로그에 메타 부착

그다음 `start_content`, `end_content` 각각에 위 메타를 붙인다.

- `start_content_analysis`
- `end_content_analysis`

이렇게 하면 각 콘텐츠 이벤트 로그에 다음 정보를 동시에 갖게 된다.

- `user_id`
- `content.id`
- `content_difficulty_final`
- `interest_count`
- `start_count`

이후 이 로그를 다시 `seg_4grp`가 붙은 유저 마스터와 `user_id` 기준으로 결합해,

- 유지 그룹별 난이도 분포
- 유지 그룹별 인기도 요약

을 계산했다.

## 5. 현재 콘텐츠 분석 구조

### 5-1. 난이도 분석

난이도는 유지하고 있다.

분석 방식:

- `start_content` 기준 난이도 분포
- `end_content` 기준 난이도 분포

각 그룹에 대해 다음을 계산한다.

- 이벤트 수
- 해당 난이도를 소비한 유저 수
- 해당 난이도 콘텐츠 수
- 그룹 내 비율

현재 관찰된 전반적 패턴:

- 모든 그룹에서 `intermediate` 비중이 가장 큼
- `start_content` 대비 `end_content`에서는 `beginner` 비중이 상대적으로 확대됨
- `hard`는 전체적으로 비중이 매우 작음
- `6m_plus_monthly_only` 그룹에서는 `hard` 시작 로그는 있었지만 완료 로그는 관측되지 않음

이 결과는 다음처럼 해석할 수 있다.

- 시작 단계에서는 `intermediate` 중심 소비가 일반적임
- 완료 단계에서는 상대적으로 쉬운 콘텐츠가 더 많이 남는 경향이 있음

### 5-2. 인기도 분석

인기도는 더 이상 사분면으로 나누지 않고, 콘텐츠 메타값의 요약통계로 본다.

각 그룹별로 다음을 계산한다.

- 소비한 콘텐츠 이벤트 수
- 소비한 유저 수
- 소비한 유니크 콘텐츠 수
- `interest_count`의 평균, 중앙값, 분위수
- `start_count`의 평균, 중앙값, 분위수

그리고 이를 `start_content` 기준, `end_content` 기준으로 각각 본다.

현재 관찰된 전반적 패턴:

- `with_annual_in_first_chain` 그룹은 시작/완료한 콘텐츠 모두에서 평균 인기도 지표가 상대적으로 높음
- `0_to_2m`, `3_to_5m`, `6m_plus_monthly_only`는 서로 유사하지만, 장기 월간 유지 그룹일수록 아주 약하게 더 niche한 콘텐츠로 이동하는 신호도 보임
- 중앙값 차이는 평균 차이보다 작아서, 특정 상위 인기 콘텐츠 소비가 평균을 끌어올리고 있을 가능성이 있음

즉 현재 인기도 결과는 다음처럼 읽을 수 있다.

- 연간이 첫 체인에 포함된 그룹은 전체적으로 더 인기 있는 콘텐츠를 소비하는 경향이 있다
- 다만 이 차이는 그룹 전체가 일관되게 다르다기보다는, 인기 상위 콘텐츠 소비 비중 차이에서 비롯됐을 가능성이 있다

## 6. 최근 의사결정 정리

이번 채팅에서 최종적으로 정리한 분석 방향은 다음과 같다.

### 유지한 것

- 유저 마스터 기반 분석 구조
- `start_content` / `end_content`를 분리해서 보는 구조
- 콘텐츠 난이도 분석
- 콘텐츠 인기도를 글로벌 기준으로 정의하는 방식

### 수정한 것

- 단일 `consecutive_sub_months` 중심 해석에서 벗어나
  - `first_chain_months`
  - `max_chain_months`
  - `total_paid_months`
  - `reactivated_after_gap`
  - `annual_in_first_chain`
  로 분리
- 세그먼트를 `seg_4grp`로 재정의
- `12개월 이상` 집단을 연간 포함 여부로 분리

### 폐기한 것

- 콘텐츠 인기도 사분면 분석
- 현재 단계에서의 완강률 메인 분석

완강률은 계산 자체는 가능했지만, 다음 이유로 메인 흐름에서는 제외했다.

- `end_content`가 완강의 완전한 정의인지 불명확
- 난이도 높은 구간은 표본 수가 너무 작음
- 인기도 사분면과 결합하면 해석 안정성이 더 떨어짐

## 7. 현재까지의 결론

현재 분석 파이프라인은 다음처럼 정리할 수 있다.

1. 구독 로그 정제
2. 유저 마스터 생성
3. 구독 유지 지표 파생
4. 회원가입 정보 결합
5. 최종 유지 그룹(`seg_4grp`) 생성
6. 콘텐츠 메타 생성
7. 유저-콘텐츠 결합
8. 난이도 분포 및 인기도 요약 비교

즉 이번 분석은 단순히 “누가 오래 구독했는가”를 보는 것이 아니라,

- 어떤 유형의 구독 경로를 가진 유저가
- 어떤 난이도의 콘텐츠를
- 얼마나 인기 있는 콘텐츠 중심으로
- 시작하고 완료했는지

를 함께 해석하는 구조로 발전했다.

현재 기준으로는 다음 두 축이 가장 해석력이 높다.

- 난이도 분포
- 콘텐츠 인기도 요약 통계

이 두 축을 중심으로 멘토링에서 논의하면, 지금까지의 모델링/전처리 의사결정과 결과를 비교적 일관되게 설명할 수 있다.
